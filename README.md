# 私聊文字单次分段发送

避免普通聊天中 `send_message_to_user` 先发送文字，模型随后又在最终回复里改写、重复发送。

## 安装和配置

1. AstrBot 插件管理 → 从链接安装，填入本仓库地址。
2. 在目标私聊使用 `/sid` 获取完整会话标识。
3. 插件配置 → `sessions` 加入该标识并保存。默认列表为空，不影响任何会话。
4. 如需多条气泡，在 AstrBot「配置文件 → 扩展功能 → 分段回复」启用按换行分段，在人格里要求一条气泡一行。

本插件不设置原生分段参数；分段阈值及延时仍由 AstrBot 控制。请注意原生“字数阈值”可能是超过后不分段，按实际版本说明配置。

## 工作方式

- 只包装单次请求的发送工具副本，不修改全局工具或核心文件。
- 白名单私聊中，发往当前会话的纯文字工具调用仅暂存，返回明确的“尚未发送”结果，引导模型通过最终回复一次输出。
- 同一轮重复的完全相同暂存文本不累加。最终回复为空时，以暂存正文兜底。
- 图片、语音、视频、文件及混合媒体继续走原发送工具。
- 跨会话发送继续走原工具及其权限校验；其他会话不受影响。
- 停用插件即可恢复原行为，已开始的请求可能继续使用该请求的工具副本。

## 兼容范围和限制

已在 AstrBot 4.29.1、OneBot v11 私聊中实测。需要 Python 3.10+。
其他 4.x 版本未逐个验证，依赖 `ProviderRequest.func_tool`、`ToolSet` 和内置发送工具的 `call()` 接口。
本插件不保证拦截其他插件直接调用平台发送接口的文字，也不对“文字+图片”混合消息做语义去重。
会话白名单中仅 `FriendMessage` 生效；当前不是群聊去重插件。主动任务是否经过请求钩子取决于其实现，若经过相同钩子且命中白名单，纯文字也会采用本规则。
它不是通用流式去重器；推荐用于非流式普通聊天。不要同时叠加多个改写发送工具的补丁。

## 测试

```bash
python -m unittest discover -p "test_*.py" -v
```

测试使用内存发送端，不访问模型或聊天平台，覆盖重复工具调用、最终改写、空回复兜底、媒体及其他会话不变、默认不启用任何会话。

## 隐私与许可

本仓库不包含真实会话 ID、聊天记录、凭据或服务器配置。运行时仅在当前事件对象中暂存文本，不主动外传或持久化日志正文。MIT License。
